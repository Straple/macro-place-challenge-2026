# Macro Placement Challenge — Правила скоринга Гран-при (v2.0)

> Русский перевод [SCORING.md](../SCORING.md). Оригинал на английском — источник истины при расхождениях.

Этот документ описывает систему оценки для Гран-при ($20,000).

## Обзор

Оценка Гран-при состоит из **двух стадий**:

1. **Feasibility** — жёсткие ограничения тайминга (pass/fail)
2. **Scoring** — детерминированное ранжирование через геометрическое среднее улучшений

Только сабмишены, прошедшие **Stage 1** на **всех дизайнах**, eligible для Гран-при.

---

## Какие сабмишены оцениваются?

**Топ-7 сабмишенов по Tier 1 proxy cost** (IBM benchmarks) оцениваются через полный OpenROAD flow на NG45 дизайнах.

Оцениваемые дизайны:
- `ariane133` (публичный)
- `ariane136` (публичный)
- `mempool_tile` (публичный)
- `nvdla` (публичный)
- 1–2 скрытых NG45 дизайна (для предотвращения переобучения)

---

## Baselines

Baselines генерируются прогоном **Simulated Annealing (SA)** и **RePlAce (RP)** через **тот же OpenROAD evaluation flow**, что используется для сабмишенов.

Для каждого дизайна измеряются:
- **WNS** — Worst Negative Slack (нс). Выше (ближе к 0) — лучше.
- **TNS** — Total Negative Slack (нс). Выше (ближе к 0) — лучше.
- **Area** — Площадь ядра (μm²). Меньше — лучше.

Baseline числа будут опубликованы для всех публичных дизайнов после генерации.

---

## Stage 1 — Feasibility (ограничения тайминга)

Сабмишен **не должен регрессировать тайминг** ниже обоих baselines на любом дизайне.

Для каждого дизайна:

```
WNS_sub ≥ min(WNS_SA, WNS_RP)
TNS_sub ≥ min(TNS_SA, TNS_RP)
```

### Интерпретация

- Ты **не можешь быть хуже обоих baselines** по WNS или TNS на любом дизайне.
- Можешь сравняться с одним baseline и обойти другой.
- Если хотя бы одно условие не выполнено на **любом** дизайне → сабмишен **дисквалифицируется** из Гран-при.

---

## Обработка ORFS-сбоев

Если OpenROAD падает на любом дизайне (выходит с non-zero до получения WNS/TNS/Area), сабмишен технически дисквалифицируется из Гран-при. На практике мы свяжемся с командой и поработаем над разрешением проблемы — независимо от того, на нашей стороне причина (баг evaluator'а, проблема нетлиста) или на стороне placer'а (placement-выбор, через который ORFS не может маршрутизироваться).

Evaluator автоматически делает следующее за placer'а:
- Snap-ит позиции макросов на manufacturing grid.
- Итеративно раздвигает макросы для поддержания ≥12 μm зазора (для маршрутизации PDN канала нужно ~10 μm между соседними макросами). Это происходит **только на Tier 2**, после масштабирования размещения в координаты ядра ORFS; Tier 1 proxy cost использует твои координаты без изменений. Pre- и post-push координаты логируются в сайдкар `macros.tcl.spacing_diff.txt` в директории результатов ORFS — можно увидеть точно, что было сдвинуто и насколько. Чтобы сохранить полный контроль над Tier 2 координатами, оставляй ≥12 μm между макросами в своём размещении.
- Escape инстанс-имён для нетлистов Genus.

Placer отвечает за: zero overlaps, нахождение в границах canvas, выбор ориентаций макросов и любые другие решения, влияющие на дальнейшую трассируемость в ORFS.

Ранжирование Tier 1 (Proxy Prize) не зависит от Tier 2 / ORFS результатов.

## Stage 2 — Скоринг (геометрическое среднее ratios)

Все feasible-сабмишены ранжируются с помощью **одного скалярного score**, вычисляемого из ratio улучшений. Этот подход:

- Естественно обрабатывает метрики разных шкал.
- Приоритизирует улучшение тайминга (WNS наиболее важен, затем TNS), сохраняя Area в score.
- Использует **взвешенное геометрическое среднее** с фиксированными весами **(WNS:3, TNS:2, Area:1)**, отражающими относительную важность каждой метрики в финальном дизайне.

### Шаг 1 — Вычислить средние baselines

Для каждого дизайна — среднее SA и RePlAce:

```
WNS_avg = (WNS_SA + WNS_RP) / 2
TNS_avg = (TNS_SA + TNS_RP) / 2
Area_avg = (Area_SA + Area_RP) / 2
```

### Шаг 2 — Вычислить ratio улучшений

Для каждого дизайна:

```
R_WNS  = WNS_avg  / WNS_sub       (оба отрицательные; менее отрицательный числитель — baseline, ratio > 1 значит сабмишен лучше)
R_TNS  = TNS_avg  / TNS_sub       (оба отрицательные; ratio > 1 значит сабмишен лучше)
R_Area = Area_avg / Area_sub      (меньшая площадь лучше, поэтому avg в числителе; ratio > 1 значит сабмишен меньше)
```

### Шаг 3 — Вычислить per-design score

Через **взвешенное геометрическое среднее** с весами (WNS:3, TNS:2, Area:1):

```
Design_Score = (R_WNS^3 × R_TNS^2 × R_Area^1) ^ (1/6)
```

- **Score > 1.0** → лучше среднего baseline
- **Score = 1.0** → точное совпадение с baseline
- **Score < 1.0** → хуже среднего baseline

### Почему такие веса?

WNS — самая важная цель: чип, проваливший свою worst-case path, проваливается, независимо от среднего поведения и площади. TNS схватывает широту таймингoвых нарушений и идёт следующим по важности. Area важна, но вторична после закрытия тайминга на этом этапе flow. Соотношение 3:2:1 отражает этот порядок без обнуления любой метрики.

В лог-терминах **1% улучшение WNS** даёт в 3× больший вклад в score, чем 1% улучшение Area, и в 1.5× больше, чем 1% улучшение TNS.

### Шаг 4 — Вычислить общий score

```
Total_Score = геометрическое среднее Design_Scores по всем оцененным дизайнам
            = (Design_Score_1 × Design_Score_2 × ... × Design_Score_N) ^ (1/N)
```

**Наивысший Total Score выигрывает Гран-при.**

### Пример

Допустим, для `ariane133`:
- SA baseline: WNS = -1.4 нс, TNS = -11,000 нс, Area = 4,300,000 μm²
- RePlAce baseline: WNS = -1.2 нс, TNS = -9,000 нс, Area = 4,100,000 μm²
- Средний baseline: WNS = -1.3 нс, TNS = -10,000 нс, Area = 4,200,000 μm²
- Сабмишен: WNS = -0.8 нс, TNS = -6,000 нс, Area = 4,000,000 μm²

```
R_WNS  = -1.3    / -0.8     = 1.625   (на 62.5% лучше WNS)
R_TNS  = -10000  / -6000    = 1.667   (на 66.7% лучше TNS)
R_Area = 4200000 / 4000000  = 1.050   (на 5% меньше площадь)

Design_Score = (1.625^3 × 1.667^2 × 1.05^1) ^ (1/6)
             = (4.291 × 2.779 × 1.05) ^ (1/6)
             = (12.521) ^ (1/6)
             = 1.524
```

Этот сабмишен получает **1.524** на ariane133 — примерно на 52% лучше среднего baseline, с подчёркнутым выигрышем по WNS и TNS из-за весов (3,2,1). При равных весах (1,1,1) тот же сабмишен получил бы 1.417.

## Тай-брейкинг

Если у двух сабмишенов одинаковый Total Score:

1. Выше геометрическое среднее R_TNS по дизайнам.
2. Выше геометрическое среднее R_WNS по дизайнам.
3. Выше геометрическое среднее R_Area по дизайнам.

---

## Граничные случаи

- **Сабмишен достигает WNS = 0 и TNS = 0**: clock period ужесточается (частота повышается), и дизайн пере-оценивается итеративно, пока WNS < 0 не появится снова. Ранжирование далее использует WNS/TNS, измеренные на ужесточённом clock. Это гарантирует, что сабмишены, закрывающие тайминг на номинальном clock, всё ещё дифференцируемы по тому, *сколько frequency headroom* они дают, вместо того чтобы упереться в потолок.
  - График ужесточения фиксирован заранее (например, уменьшать period на 5% за шаг, до ограниченного числа шагов) и применяется одинаково ко всем сабмишенам для этого дизайна.
  - Baselines пере-оцениваются на ужесточённом clock только если хотя бы один baseline тоже достиг zero-slack на номинальном clock; иначе используются исходные baseline числа.
- **WNS или TNS = 0.0 для обоих baselines (но у сабмишена есть нарушения)**: ratio этой метрики исключается из geometric mean для этого дизайна; веса оставшихся метрик ренормализуются, чтобы их сумма по-прежнему была 6.

## Запрещённые стратегии

Сабмишены могут быть дисквалифицированы, если они:

- Намеренно ухудшают тайминг для game'инга скоринга.
- Модифицируют или обходят evaluation flow.
- Хардкодят design-specific хаки под известные benchmarks.

---

## Воспроизводимость

- Оценка использует версионированный OpenROAD flow; точная версия для финального скоринга будет задокументирована вместе с результатами.
- Evaluation pipeline будет выпущен вместе с финальными результатами.
- Все сабмишены в одном раунде оценки запускаются в одинаковых условиях на одном и том же железе.

---

## Резюме

Чтобы выиграть Гран-при:

1. Быть в **топ-7 по proxy cost** (Tier 1).
2. **Пройти feasibility** — не регрессировать тайминг ниже обоих baselines на любом дизайне.
3. **Максимизировать взвешенный geometric mean score** — приоритет WNS, затем TNS, затем Area (веса 3:2:1) по всем дизайнам.

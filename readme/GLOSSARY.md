# Глоссарий — термины EDA и соревнования

> Краткие пояснения терминов, которые встречаются в README, SETUP, SCORING, leaderboard, paper'ах. Для тех, кто не из мира физического дизайна чипов.

## Основные понятия задачи

### Macro placement (размещение макроблоков)
Задача расположения больших фиксированных блоков (`macro`) на площади чипа так, чтобы оптимизировать набор метрик: длину проводов, плотность, перегруженность маршрутизации, тайминг, площадь.

### Floorplan (флорплан, план кристалла)
Высокоуровневый план чипа — как расположены блоки, питание, ввод-вывод. Macro placement — часть floorplan'а.

### Placement (плейсмент, размещение)
Шаг в потоке проектирования: разместить элементы (макросы и/или стандартные ячейки) в координатах. После placement идёт **routing** (трассировка).

### Routing (маршрутизация, трассировка)
Шаг после placement: проложить провода между пинами по слоям металла.

### Canvas (канвас)
Прямоугольная область чипа, на которой размещаются макросы. Задаётся `canvas_width × canvas_height` в микронах (μm). В этом репо `benchmark.canvas_width / canvas_height`.

### Macro (макроблок, макрос)
Большой "готовый" блок — обычно SRAM, ROM, аналоговый IP-блок, ML-ускоритель и т.п. Имеет фиксированный размер `width × height`. В соревновании их размещаем мы.

### Hard macro (жёсткий макро)
Реальный физический блок (SRAM и т.п.) с фиксированной геометрией. Между hard macros **не должно быть пересечений** (это жёсткое ограничение, проверяется в evaluator).

### Soft macro (мягкий макро)
Абстракция в evaluator'е: кластер стандартных ячеек, представленный как один прямоугольник для целей быстрой оценки density/congestion. Soft macros **могут пересекаться**, размер фиксирован при загрузке. В Tier 2 (ORFS) понятия soft macro нет.

### Standard cell (стандартная ячейка, "стенцелл")
Маленький логический блок (NAND, FF и т.д.) из библиотеки. Их сотни тысяч. В нашей задаче они агрегированы в soft macros.

### Pin (пин)
Точка соединения макроса с проводом. У каждого hard macro несколько пинов на разных краях. Координата пина = позиция центра макроса + смещение пина (`macro_pin_offsets`).

### Port (порт)
Пин на границе чипа (I/O). Используется для соединения с внешним миром, обычно зафиксирован.

### Net (нет, цепь, провод)
Электрическое соединение, объединяющее набор пинов. Один net = один провод (логически). У net есть `weight` — насколько он критичен.

### Netlist (нетлист)
Описание всех нетов и связей в дизайне. Хранится в `PlacementCost` (внутри plc), также частично в `benchmark.net_nodes` / `net_pin_nodes`.

### Fixed macro (зафиксированный макро)
Макро, который **нельзя двигать** (обычно I/O или предразмещённый блок). В коде — `benchmark.macro_fixed[i] == True`.

## Метрики (что измеряем)

### Wirelength (длина проводов)
Главная метрика placement: суммарная длина всех проводов между пинами. Хочется минимизировать.

### HPWL (Half-Perimeter Wirelength)
Самый частый способ оценки wirelength: для каждого net'а строим bounding box (минимальный прямоугольник, охватывающий все его пины) и берём половину периметра. Сумма по всем net'ам.

```
HPWL_net = (max_x - min_x) + (max_y - min_y)
HPWL_total = Σ HPWL_net × weight_net
```

### Density (плотность)
Насколько плотно макросы упакованы в каждой ячейке сетки (grid). В этом evaluator'е — топ-10% самых плотных ячеек. Слишком плотно = негде расположить стандартные ячейки.

### Congestion (перегруженность маршрутизации)
Оценка того, насколько провода будут "толкаться" в каждой routing-области. Топ-5% самых congested сегментов. Если congestion высокий, маршрутизация может не сойтись.

### Overlap (пересечение)
Когда два макроса физически перекрываются. **Hard-hard overlap = DQ** (дисквалификация). Soft могут перекрываться.

### Proxy cost (прокси-стоимость)
Главная метрика Tier 1, агрегирующая wirelength + density + congestion с весами:
```
proxy_cost = 1.0 × wirelength + 0.5 × density + 0.5 × congestion
```
Считается через `compute_proxy_cost()`.

### WNS (Worst Negative Slack)
**Худший негативный запас тайминга** в наносекундах. Метрика Tier 2 (ORFS).
- `slack` пути = (требуемое время прихода сигнала) − (фактическое)
- Если slack < 0 → путь не успел = ошибка тайминга
- WNS = минимальный (худший) slack по всем путям
- **Выше (ближе к 0) = лучше.** Цель: WNS ≥ 0 (полное закрытие тайминга).

### TNS (Total Negative Slack)
**Сумма всех отрицательных slack'ов** по всем путям. Показывает, насколько массово нарушается тайминг (а не только один худший путь).
- **Выше (ближе к 0) = лучше.**

### Area (площадь)
Площадь ядра чипа (μm²) после полного flow. Метрика Tier 2.
- **Меньше = лучше.**

### Slack (запас)
Запас по времени для конкретного timing path. Положительный = успели, отрицательный = провалились.

### Timing (тайминг)
Общий термин для всего, что связано со временем прихода сигналов. Закрытие тайминга = WNS ≥ 0.

## Алгоритмические термины

### SA (Simulated Annealing, имитация отжига)
Классический метаэвристический алгоритм: случайные ходы, принятие плохих с убывающей температурой. Baseline 1 в этом соревновании.

### RePlAce
Аналитический placement-алгоритм на основе градиентного спуска по дифференцируемой функции стоимости. Baseline 2, **сильнее SA**. RePlAce baseline = 1.4578 (порог отсечки).

### ePlace
Предшественник RePlAce, использует electrostatic-аналогию для density (макросы как заряды).

### DREAMPlace
GPU-ускоренная PyTorch-реализация ePlace/RePlAce. **Доминирует в топ-10** leaderboard. См. [github.com/limbo018/DREAMPlace](https://github.com/limbo018/DREAMPlace).

### Force-directed (силовое размещение)
Подход, при котором макросы притягиваются друг к другу через net'ы (как пружины) и отталкиваются для density.

### LNS (Large Neighborhood Search)
Метаэвристика: итеративно "destroy" — убрать часть решения, "repair" — восстановить иначе. Принимать улучшения. См. [ALGORITHMS.md](ALGORITHMS.md).

### ALNS (Adaptive LNS)
LNS с адаптивной выборкой operator'ов на основе их прошлой успешности.

### Spectral placement
Использует собственные векторы лапласиана графа netlist'а как координаты — даёт хороший начальный seed.

### Quadratic placement
Минимизация квадратичной функции wirelength через решение системы линейных уравнений. Быстро, но не учитывает overlaps.

### Min-cut bisection
Рекурсивно разрезает netlist на 2 половины с минимальным числом пересекающих net'ов, пока не дойдёт до позиций.

### Legalization (легализация)
Послеоперация: подвинуть макросы так, чтобы устранить overlaps и оставить корректные позиции (на grid'е, в bounds).

### GNN (Graph Neural Network)
Графовая нейросеть. Применяется для предсказания placement по netlist'у.

### RL (Reinforcement Learning)
Обучение с подкреплением. Google использовали его для placement (Nature 2021), но воспроизводимость спорная (см. background paper #1, #2, #3 в README).

## Технические термины проекта

### .plc (placement file)
Текстовый формат TILOS, описывает initial placement. В `load_benchmark_from_dir` ищется как `initial.plc` в директории.

### .pb.txt (protobuf netlist)
Текстовый protobuf формат TILOS для нетлиста. В `load_benchmark_from_dir` ищется как `netlist.pb.txt`.

### .pt (PyTorch tensor file)
Бинарный формат PyTorch. В `benchmarks/processed/public/` лежат уже сериализованные `Benchmark` объекты — можно загрузить через `Benchmark.load(path)` без TILOS submodule.

### PlacementCost (`plc`)
C++/Python обёртка из TILOS MacroPlacement, которая считает proxy cost. Возвращается из `load_benchmark_from_dir` вторым элементом.

### Grid / Grid cell (сетка / ячейка сетки)
Канвас разбит на `grid_rows × grid_cols` ячеек. Density считается по ячейкам, congestion — по routing-сегментам между ячейками.

### Manufacturing grid
Минимальный шаг сетки для физического изготовления (например, 0.005 μm). Tier 2 evaluator снапает координаты на эту сетку.

### DEF (Design Exchange Format)
Стандартный формат для описания placement+routing для EDA-инструментов. `def_writer.py` экспортирует placement в DEF для OpenROAD.

### TCL
Скриптовый язык, на котором пишутся команды OpenROAD/Innovus. `scripts/generate_macro_placement_tcl.py` генерирует TCL команды.

### ORFS (OpenROAD Flow Scripts)
Открытый PnR (Place-and-Route) flow на основе OpenROAD. Используется для Tier 2 оценки. См. [github.com/The-OpenROAD-Project/OpenROAD-flow-scripts](https://github.com/The-OpenROAD-Project/OpenROAD-flow-scripts).

### OpenROAD
Открытый EDA-инструмент для физического дизайна. Запускает synthesis → floorplan → placement → CTS → routing.

### CTS (Clock Tree Synthesis)
Шаг построения дерева тактового сигнала. Один из этапов после placement.

### PnR (Place-and-Route)
Place-and-Route — общее название этапа размещения и трассировки.

### NG45 (NanGate45)
Открытая библиотека стандартных ячеек на 45нм. На ней оценивается Tier 2 (ariane133, ariane136, mempool_tile, nvdla).

### ASAP7
Открытая 7нм библиотека от ASU. В `benchmarks/processed/public/` есть ASAP7 версии — для эксперимента, не для оценки.

### IBM ICCAD04
Бенчмарк-набор из 18 задач (ibm01..ibm18) от IBM, опубликован в 2004. Стандарт академической литературы по placement. Tier 1 этого соревнования = ICCAD04 ibm01..ibm18 (без ibm05).

### TILOS MacroPlacement
Открытый репо ([github.com/TILOS-AI-Institute/MacroPlacement](https://github.com/TILOS-AI-Institute/MacroPlacement)) с evaluator'ом, baseline'ами SA/RePlAce и benchmark'ами.

## Ориентация макросов

### N, FN, FS, S (Klein-4)
Разрешённые ориентации hard macros в этом соревновании:
- **N** (North) — нормальная
- **FN** (Flip-N) — отражённая по вертикали
- **FS** (Flip-S) — повёрнутая на 180°, потом отражённая
- **S** (South) — повёрнутая на 180°

### R90, R270, FE, FW (запрещены!)
Ориентации с поворотом на 90° запрещены — fakeram45 SRAM не предусматривает таких поворотов (pin access не работает).

### orientations.pt (опциональный сайдкар)
Файл с ориентациями для Tier 2. Если не предоставлен — все макросы остаются в исходной (N) ориентации.

## Жаргон leaderboard / коммьюнити

### "self-reported"
Команда заявила свой score. Не верифицировано судьями.

### "verified"
Судьи запустили код в чистом env'е и подтвердили заявленный score (или скорректировали).

### "DQ" (Disqualified)
Сабмишен дисквалифицирован (overlap'ы, runtime > 1 час, hardcoded под benchmark, и т.п.).

### "pending"
Сабмишен ждёт верификации.

### "DREAMPlace++"
Не отдельный продукт, а условное название "DREAMPlace плюс наши улучшения". Так называет себя топ-2 (MTK).
